How I Build

Full stack, explained

A full-stack app has layers that work together. Here is what each layer does, and how I built it in my Khanu Learning capstone.

Front endReact + ViteWhat the user sees and clicks
→
Back endNode.js + ExpressREST API, rules and security
→
DatabaseMongoDB + MongooseUsers, services, bookings
+
AI serviceGoogle GeminiExplains recommendations

1Front end (client)

The part that runs in the browser: layout, buttons, forms and screens. It sends requests to the back end and shows the results.

  • HTML for structure, CSS for design, JavaScript for behavior
  • React components and state; React Router for pages
  • Responsive design for phones, tablets and desktops

In Khanu: searchable services, category filters, booking screens, light/dark theme and an animated study buddy.

2Back end (server)

The program on the server that receives requests, checks them, applies the business rules and talks to the database.

  • Node.js runs JavaScript on the server
  • Express defines REST API routes (GET, POST, DELETE)
  • Validation stops bad or missing data

In Khanu: APIs for registration, login, recommendations and bookings.

3Database

Where data is saved permanently, so it is still there after a refresh or on another device.

  • MongoDB stores data as documents
  • Mongoose defines models and how they connect
  • Create, read, update and delete (CRUD) operations

In Khanu: connected user, service and booking models; users create, review and cancel their own sessions.

4Authentication & security

Making sure people are who they say they are, and can only touch their own data.

  • bcrypt hashes passwords (never stored as plain text)
  • JWT tokens keep users logged in
  • Ownership checks protect each account; API keys stay in environment variables, never in public code

In Khanu: live checks confirm one user cannot see or cancel another user's bookings.

5APIs & AI integration

Connecting to outside services to add data and smart features.

  • REST APIs with fetch and async/await
  • Google Gemini, OpenAI and the browser's Web Speech API
  • Retries and fallbacks when a service is down

In Khanu: catalog scoring ranks sessions, then Gemini explains the best match; a labeled fallback keeps the app usable.

6Deployment, domains & testing

Getting the app onto the internet and making sure it keeps working.

  • Git and GitHub for version control
  • Render, Vercel, GitHub Pages and Cloudflare Workers for hosting
  • Custom domains and DNS; automated and live testing

In Khanu: deployed on Render plus a GitHub Pages front end, with 15 passing automated tests.

Full-Stack Capstone

Khanu Learning — AI-Assisted Tutoring & Booking

A full-stack app that helps learners go from "I need help" to booking a suitable tutoring session based on their goal, subject, level and budget.

The Problem

Learners struggle to know which tutor fits their goal, level and budget, and then have to book and track sessions somewhere else.

The Solution

One app that searches a tutoring catalog, scores and ranks matching sessions, uses Google Gemini to explain why the top match fits, and handles accounts and bookings in the same place.

ReactViteNode.jsExpressMongoDBMongooseJWTbcryptGoogle GeminiRenderGitHub Pages

What I Built

  • Frontend: React and Vite interface with searchable services, category filters, service details, light/dark themes and an animated study buddy.
  • Backend: Express REST APIs for registration, login, validation, recommendations and bookings, protected with password hashing, JWT authentication and ownership checks.
  • Database: MongoDB and Mongoose models for users, services and bookings; users create future appointments, review their sessions and cancel their own bookings.
  • AI: catalog scoring ranks sessions, then Gemini explains the top recommendation, with clearly labeled fallback results when the AI provider is unavailable.
  • Testing: 15 passing automated tests, plus live checks of login, bookings, filtering and account isolation.
  • Deployment: full app on Render plus an additional GitHub Pages frontend; secrets kept in environment variables, not in code.

Engineering Takeaway

Connecting three application layers taught me to handle API failures, debug deployment settings, and document both verified features and remaining limitations.
